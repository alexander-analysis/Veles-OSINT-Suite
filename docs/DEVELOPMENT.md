# Development Guide

## Setup

```bash
cd backend
python -m venv venv && venv/Scripts/activate       # source venv/bin/activate on Linux/macOS
pip install -r requirements.txt
python run.py                                      # API on :8000, bots start immediately

cd frontend
npm install
npm run dev                                        # UI on :5173, /api proxied to :8000
```

Set `SCHEDULER_ENABLED=false` in `backend/.env` to run the API without the
bots (useful when iterating on endpoints).

## Tests and lint

```bash
cd backend
venv/Scripts/python -m pytest -q          # 47 tests, ~4 s, no network (temp SQLite DB)
venv/Scripts/python -m flake8 app tests migrations

cd frontend
npm run lint
npm run build
```

CI (`.github/workflows/ci.yml`) runs the same on Python 3.11 and 3.13 and
Node 22.

## Code layout

```
backend/app/
  api/            FastAPI routers (health, market, maritime, sanctions, admin, stream)
  analysis/       pure functions: detectors, matching, geospatial, risk, correlation
  bots/           runtime (bot event loop), scheduler, market/sanctions/maritime bots
  integrations/   exchange, AIS and sanctions-list clients
  models/         SQLAlchemy models (schema owned by Alembic migrations)
  reports/        PDF/JSON report builders
  schemas/        Pydantic response models
  utils/          logger, time, config store, serialization
  auth.py         optional API token middleware
  notifications.py webhook / e-mail alerts and digest
frontend/src/
  pages/          one component per route (lazy-loaded)
  components/     common, market, maritime, intelligence
  hooks/          useFetch (polling), useWebSocket (auto-reconnect)
  services/       api.js (token-aware fetch), charts.js
```

## Conventions that matter

* **Timestamps are naive UTC** in Python and the DB. Use `app.utils.time.utcnow()`
  and `to_unix_ms()`; `datetime.timestamp()` on a naive value silently assumes
  local time.
* **Bots run on one dedicated asyncio loop** (`app/bots/runtime.py`).
  APScheduler jobs only submit coroutines via `_on_loop(...)`; long-lived
  streams (Binance liquidations, aisstream, NMEA TCP) live on that loop too.
  Blocking DB work inside bot coroutines goes through `asyncio.to_thread`
  when it is heavy (list refresh, AIS ingest).
* **Detectors are pure**: `analysis/*` takes data in, returns records out;
  persistence, de-duplication and audit entries live in the bots. Test
  detectors with synthetic data (see `tests/test_analysis.py`,
  `tests/test_maritime.py`).
* **Every operator action and every detection writes an `AuditLog` row**;
  the table is append-only (ORM listeners + SQLite triggers).
* **Config split**: secrets only in `.env` (`settings.key("NAME")` treats the
  `your_..._here` placeholders as unset); tunables in `settings.yaml`, read at
  each run via `config_store.get_config()`.

## Adding a detector

1. Write a pure function in `app/analysis/<module>.py` returning a dataclass.
2. Call it from the relevant bot method, de-duplicate against existing rows,
   persist, add an `AuditLog` entry, optionally `stream.publish(...)` and
   `notifications.send_alert(...)`.
3. Expose it through the router + Pydantic schema; add a frontend component.
4. Add a synthetic-data unit test and an API test.

## Adding an AIS source

Implement a client producing `AISPosition` records (see
`integrations/ais_common.py`): either `async fetch_positions()` (polled) or a
long-lived task with `drain()` (streamed). Register it in
`MaritimeBot.ensure_sources()` and add an entry to `maritime.ais_sources` in
`settings.yaml`. Key-gated sources must stay off when their credential is
missing (record the reason in `source_errors`).

## Schema changes

```bash
cd backend
venv/Scripts/alembic revision --autogenerate -m "describe change" --rev-id 004
# review migrations/versions/004_*.py (SQLite batch mode; constraints must be named)
venv/Scripts/python -m pytest -q      # tests run every migration on a fresh DB
```

`Base.metadata` has a naming convention so autogenerated constraints get
stable names. The app applies `alembic upgrade head` at startup.

## Releasing

Bump `backend/app/__init__.py` and `frontend/package.json`, update the
README status, tag, push. On the Pi: `git pull && bash deployment/pi-setup.sh`.
